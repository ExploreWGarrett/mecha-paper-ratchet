# Implementation Kickoff Brief

Open this note when the project is finally ready to stop reviewing and start coding.

This is the shortest high-signal handoff into development.

---

## Build order
Start in this order:
1. **wrench close-range commitment family**
2. **Popper cadence family**
3. **Gun Kata / alternation fusion**

Do not reorder this unless the readiness re-run explicitly justifies it.

---

## First coding target
### Wrench close-range commitment family
Build toward:
- third-hit mark application
- spin pull / close-range grouping
- catch-confirm into a stronger next melee hit

### What this first pass should prove
- close-range commitment is fun enough to be the backbone of the build language
- visible setup/payoff works in motion
- melee-first identity gets stronger instead of blurrier

### What this first pass must not become
- hidden DPS inflation
- crowd-control sludge
- a back door into recall detonation logic
- safe passive value that removes commitment

---

## Non-negotiables during implementation
- combat feel comes before progression cleverness
- 3D readability beats theoretical coolness
- melee-first remains true
- the Popper complements the wrench, not replaces it
- anti-exploit discipline is part of design
- scope control is a feature

## The questions the first pass must answer
- Did it create a new close-range decision?
- Can the player feel when setup becomes payoff?
- Does it remain readable in a crowd?
- Does it reinforce melee-first identity?
- Did it create a cheap repeatable loop?

---

## If the pass succeeds
Then move to:
1. Popper cadence family
2. then alternation fusion

## If the pass fails
Do not stack more features on top.
Instead:
- retune
- document what failed
- reassess whether the family shape is right

---

## Short version
When coding starts, the mission is simple:

> make committed wrench play more expressive without making the game muddier, safer, or easier to break.

If that works, the rest of the planned sequence becomes worth building.
