# Mecha Paper Ratchet Design Commandments

This note is the short ruleset for what the game should and should not become.

It turns the inspiration authority map into practical constraints.
The goal is to stop the project from slowly drifting into a blur of half-matched reference ideas.

---

## 1. Combat feel comes before progression cleverness
If the player baseline is not fun, no upgrade system will save it.

That means:
- movement feel wins first
- lock-on clarity wins early
- melee/ranged alternation must feel good before the progression layer deepens
- upgrades should enhance a fun loop, not rescue a bad one

### Therefore
- do not add more progression complexity just because the current build needs more “content”
- use progression to sharpen the toybox, not distract from weak combat feel

---

## 2. Weird weapons matter more than generic DPS language
This game should sound like itself.
That means it should favor:
- object-weapon personality
- unusual attack reads
- comic/paper exaggeration
- authored absurdity

over bland language like:
- rifle upgrade A
- damage buff B
- fire-rate node C

### Therefore
- the wrench and Popper should keep distinctive toy-like identities
- future weapons should feel like memorable objects, not anonymous equipment slots
- if a system choice makes weapons more interchangeable, that is usually the wrong direction

---

## 3. 3D readability beats reference coolness
A cool idea that does not read in space is not a good idea for this project.

That means:
- combat spacing must stay understandable
- projectile behavior must stay legible
- boomerang paths must be readable
- enemy retaliation windows must remain visible

### Therefore
- if a weird upgrade path clashes with 3D clarity, clarity wins
- if a behavior is exciting in theory but becomes noisy in motion, simplify it
- spectacle is welcome, but only when the player can still parse it under pressure

---

## 4. Melee-first must remain true even when guns grow
The Popper and later ranged routes should expand the game, not quietly replace its identity.

That means:
- the wrench remains foundational
- ranged pressure should complement melee commitment
- thrown-state tension should stay meaningful
- the player should not naturally drift into a permanently safer gun-only dominant route

### Therefore
- gun routes should support alternation, setup, and spacing — not invalidate close-range play
- fallback while the wrench is out should stay useful but weaker than full wrench control
- if ranged routes erase the value of close-range commitment, the design has drifted

---

## 5. Synergy should create decisions, not just multiplication
The point of upgrades is not only to make numbers bigger.
The point is to create:
- new timings
- new setups
- new payoffs
- new route choices
- new risk/reward questions

### Therefore
- raw stat boosts are acceptable as fuel, not as the whole identity layer
- synergy is strongest when it changes behavior, not only output
- the best upgrades should make the player play differently, not only hit harder

---

## 6. Mutations should rewrite the attack read, not just stack on top of it
If a mutation is real, the player should feel the attack changed.

That means mutations should usually:
- change the route
- change the rhythm
- change the setup/payoff logic
- change the spatial read

not merely:
- add a hidden multiplier
- add another passive line of text

### Therefore
- treat mutation as a behavior-rewrite lane
- keep it readable and visible
- do not let mutation become a synonym for “stronger version of the same thing”

---

## 7. Fusions should feel authored, not accidental sludge
Cross-weapon synergy is good.
Unreadable interaction soup is not.

That means:
- fusions should have describable identities
- the player should be able to explain what their loop is
- support upgrades should sharpen routes, not turn everything into everything

### Therefore
- a fusion is successful when it creates a recognizable combat sentence
- fusion-of-fusion capstones should be rare and identity-defining
- if a build cannot be explained without a paragraph of exception logic, it is too muddy

---

## 8. The economy is a side-lane, not the main fantasy
Right now the game fantasy is combat expression, not economy optimization.

That means:
- money is useful but secondary
- crates are optional value, not the main event
- XP/combat progression should not be overshadowed by scavenging loops

### Therefore
- do not let crate value outshine combat rewards
- do not let money upgrades become the fastest route to run power too early
- economy systems should support combat routing, not replace it

---

## 9. Anti-exploit discipline is part of design, not cleanup
If a route can be broken cheaply, it will distort the whole game.

That means the design must watch for:
- reward duplication
- safe farming
- runaway proc math
- self-refreshing setup/payoff loops
- state-transition abuse
- thrown-state or spacing safety that preserves too much reward

### Therefore
- anti-exploit review happens before implementation, not after failure
- if a system is identity-rich but risky, gate it rather than blindly delete it
- unchecked escalation is not depth

---

## 10. Scope control is a design feature
The project gets stronger when it refuses to become five games at once.

That means:
- one strong weapon lane is better than five shallow ones
- one clear mutation family is better than broad speculative content
- one good fusion is better than ten vague ones
- one fun room is still worth more than a huge weak run shell

### Therefore
- only expand after the current layer feels real
- do not let reference breadth become implementation sprawl
- every new system should earn its cost in clarity, feel, or identity

---

## 11. Tone should stay comic, authored, and readable
The game can be strange without being random.
It can be silly without being weightless.
It can be stylized without becoming visually muddy.

### Therefore
- preserve comic/object energy
- keep exaggeration readable
- favor memorable attack/weapon language over generic sci-fi/fantasy mush
- let the paper/comic framing shape presentation, not only naming

---

## 12. When in doubt, resolve conflicts with this order
If subsystems pull in different directions, resolve them in this order:

1. **readable combat feel**
2. **core weapon identity**
3. **anti-exploit safety**
4. **upgrade/fusion sophistication**
5. **economy complexity**
6. **extra flavor ideas**

### Why this order
Because the game survives weak economy complexity.
It does not survive unreadable combat, collapsed weapon identity, or broken reward logic.

---

## Short version
If the game starts drifting, come back to this:

- make combat fun first
- keep weapons weird and memorable
- preserve 3D readability
- keep melee-first true even when ranged grows
- use synergy to create decisions, not just multiplication
- treat mutation as behavior change
- keep fusions authored and explainable
- keep economy secondary to combat expression
- catch exploits early
- protect scope constantly

## Bottom line
Mecha Paper Ratchet should become:
- readable
- weird
- authored
- melee-first
- synergy-rich
- exploit-aware

It should **not** become:
- a generic stat ladder
- a proc soup the player cannot parse
- a ranged game that happens to still have a wrench
- or a progression shell trying to hide weak combat feel
